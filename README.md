# 实习投递管家

一个**纯离线、手机优先**的实习投递记录应用，可以像 App 一样装到手机桌面。所有数据只存在你自己手机里，不上传任何服务器。

没有依赖、没有构建、没有后端。

> 🚀 **只想尽快在自己手机上用起来？直接看 [`手机上装.md`](手机上装.md)** —— 从注册 GitHub 到装到桌面，全程点鼠标，10 分钟。
> 下面这份 README 是完整说明（功能清单、PWA 原理、本地调试、数据备份策略）。

---

## 一、装到手机上（PWA）

应用已经做过 PWA 化：**装到桌面后没有地址栏，没网也能打开和记录**。

> ⚠️ 关键前提：浏览器只允许在 **https 网址**或 `localhost` 上安装 PWA。
> 用 `file://` 直接打开文件、或者用 `http://192.168.x.x` 访问，都**装不了**（应用本身仍然能用，只是不能装、不能离线）。
> 应用里的「设置 → 装到手机桌面 → 检查安装条件」会直接把当前环境到底卡在哪一条列出来。

### 路线 1：先在本机局域网真机测试（10 分钟，推荐先做这个）

**电脑上双击 `启动.cmd`（或 `start.cmd`）**，它会：

1. 自动找到电脑上的 Python（没有则提示你怎么装）
2. 启动一个带自签证书的 https 服务器
3. 自动在电脑浏览器里打开一次（顺便验证服务正常）
4. 在窗口里用大字显示**手机上要打开的网址**，形如 `https://192.168.1.23:8443/`
5. 把 vivo / OriginOS 的坑、以及连不上时的排查办法直接印在窗口里

手机连**同一个 Wi-Fi**，浏览器打开那个网址 → 提示证书不受信任时点「高级 → 继续访问」→ 然后：

- **Android**：设置 → 装到手机桌面 → **一键安装**
- **iOS**：必须用 **Safari** → 底部「分享」→ **添加到主屏幕**

**怎么确认是真安装而不是浏览器快捷方式**：打开后**没有地址栏**，而且是断网也能用的。设置 → 装到手机桌面 → **检查安装条件**，第一行「当前是不是独立 App」会直接告诉你答案。

验证完，在服务器窗口按 Ctrl+C 停止（或直接关掉那个窗口）。手机上图标照样能用 —— 这就是离线可用的证明。

> 换了 Wi-Fi 或电脑换了网络后连不上？删掉 `cert.pem` 和 `key.pem`，重新双击 `启动.cmd` 即可。

### vivo / OriginOS 用户注意

| 问题 | 处理 |
|---|---|
| 用哪个浏览器 | 优先 **Chrome** 或 **Edge**。vivo 自带浏览器也行，但部分版本只支持「添加到桌面」快捷方式，**不支持真正的 PWA 安装**——判断方法见上面的「没有地址栏 + 断网可用」 |
| **别用**微信 / QQ 内置浏览器 | 它们不能安装 PWA。要复制链接到真正的浏览器里打开 |
| 装好了但断网打不开 | vivo 后台管控比较严：设置 → 电池 → 把浏览器（或已安装的应用）设为**允许后台运行 / 不优化**，否则离线启动可能被系统杀掉 |
| 证书警告只有「返回」没有「继续」 | 换 Chrome 再试；Chrome 的「高级 → 继续前往」一般都有 |
| 数据在哪 | 数据保存在**那个浏览器**的存储里。换浏览器、清浏览器数据、卸载浏览器都会丢——所以定期导出 JSON 备份 |

### 路线 2：正式用（推荐）

把整个 `internship-tracker` 文件夹传到免费静态托管，拿到 https 网址，再按上面的步骤安装：

- **GitHub Pages**：新建仓库 → 上传文件夹里所有文件 → Settings → Pages → 选 main 分支 → 得到 `https://用户名.github.io/仓库名/`
- **Cloudflare Pages / Vercel / Netlify**：直接拖文件夹上传，立刻出网址

之后换手机只要打开同一个网址、导入 JSON 备份就能接着用。

### 路线 3：不装也能用（最省事）

只把 `index.html` 一个文件传到手机（微信文件传输助手 / 邮件附件都行），用浏览器打开即可。功能完全一样，只是没有桌面图标、不能离线（没网打不开）。

> 微信内置浏览器会缓存文件，样式不对时点右上角「在浏览器中打开」。

## 二、PWA 相关的几个文件

| 文件 | 作用 |
|---|---|
| `manifest.webmanifest` | 应用清单：名称、图标、主题色、独立窗口模式 |
| `sw.js` | Service Worker：页面走「网络优先、离线回退缓存」，图标等静态资源走「缓存优先」 |
| `icon.svg` / `icon-maskable.svg` | 图标矢量源文件（矢量，任意尺寸都清晰） |
| `icon-192.png` 等 PNG | Android 安装和 iOS 主屏幕图标。**没生成也能装**，但图标可能显示成浏览器默认图 |
| `make-icons.ps1` | 在电脑上用 .NET 自带的 System.Drawing 生成上面那几张 PNG，不依赖任何第三方库 |
| `启动.cmd` / `start.cmd` | 双击即用的启动器：找 Python、起 https 服务、打印手机网址、自动开电脑浏览器 |
| `serve-https.py` | 局域网 HTTPS 测试服务器（由启动器调用，也可自己跑：`python serve-https.py --port 9443`） |

生成 PNG 图标（可选，但建议做一次）：

```powershell
powershell -ExecutionPolicy Bypass -File .\make-icons.ps1
```

### 改了应用之后怎么让手机更新

Service Worker 会缓存应用外壳，所以改完 `index.html` 后，把 `sw.js` 顶部的版本号加一：

```js
const VERSION = 'v1';   // 改成 'v2'
```

手机下次打开时会后台拉新版本，并弹一条「有新版本，正在更新…」，然后自动刷新。

## 三、它记什么

| 模块 | 字段 |
|---|---|
| **基本信息** | 公司名称、岗位名称、工作地点、当前状态、投递链接、心动指数（1–5 星）、标签 |
| **薪资** | 薪资原文（`200/天`、`4-6k`、`8k×14薪` 都认）、日薪数字 + 单位，自动折算月薪用于对比 |
| **关键日期** | 投递截止、笔试/测评、面试时间、跟进提醒 |
| **工作内容** | 工作要求、JD 原文 |
| **联系人** | 姓名/角色、手机号/微信/邮箱（自动生成「拨号」「发邮件」按钮） |
| **备注** | 自由文本 |
| **附件** | 截图、JD 图、投过的简历版本（图片/PDF） |
| **动态时间线** | 投递、简历通过、笔试、面试（含轮次/形式/面试官/结果）、跟进催进度、Offer、被拒、备注 |

### 五个页面

- **总览** — 在库公司数 / 进行中 / 进入面试 / Offer 四个数字；投递看板（点任意状态直接筛过去）；已过关键日期的提醒；未来 N 天内（7/14/30 可调）的截止日、笔试、面试倒计时；最近动态。
- **投递** — 公司卡片列表，支持搜索（公司/岗位/城市/备注/联系方式全字段），状态筛选，六种排序（最近更新 / 心动指数 / 临近截止 / 薪资高低 / 公司名 / 流程进度）。
- **动态** — 所有事件按天分组的时间线，可按公司筛选。
- **统计** — 投递总数、面试率、Offer 率、投出去 7 天没动静的数量、状态分布、流程转化漏斗、薪资分布（含平均/最高/最低/折合日均）、城市分布、每月投递量。
- **设置** — 主题（跟随系统/浅色/深色）、提醒窗口、导出 JSON / CSV / Markdown、导入 JSON、清空数据。

### 智能的地方
- 记一条「面试」动态，状态自动推进到**面试中**；记「Offer」自动变 **Offer**；记「被拒」自动变**已挂**。状态只会往前走，不会因为补记旧事件而回退。
- 手动改状态也会自动写一条时间线记录，流程不会断。
- 详情页有「标记为下一步」的快捷按钮，按 心动待投 → 已投递 → 笔试中 → 面试中 → 已获 Offer 的顺序推进。

## 四、内置自检（可选）

在网址后面加上 `?selftest=1` 再打开，会弹出一份自检报告，检查薪资解析、日期计算、状态自动推进、统计口径、界面骨架、PWA 安装条件共 40 项左右的断言是否正常。

例如：`https://你的网址/index.html?selftest=1`

这在以下情况有用：换了新手机/新浏览器、怀疑某个数字算错了、或者我改了代码你想确认没改坏。报告全绿说明核心逻辑没问题。

## 五、数据与备份（重要）

- 数据存在浏览器的 `localStorage`，附件存在 `IndexedDB`，**都只在本机**。
- 换手机、换浏览器、清缓存、用无痕模式 → **数据不会跟过去**。
- 所以：**每周导出一次 JSON 备份**（设置 → 导出 JSON 备份），存到网盘或发给自己。
- 导出格式说明：
  - **JSON** — 完整备份，可再导入（导入是**追加**模式，不会覆盖现有数据）。
  - **CSV** — 21 列，Excel / WPS / 飞书表格直接打开，适合做进一步分析或发给别人看。
  - **Markdown** — 每家公司的完整信息 + 动态，适合贴进笔记软件存档。
  - ⚠️ JSON 备份**不包含附件图片本身**（避免文件过大），附件请单独另存。

## 六、文件说明

```
internship-tracker/
├── index.html             ← 应用本体（含全部逻辑与样式）
├── manifest.webmanifest   ← PWA 清单
├── sw.js                  ← Service Worker（离线缓存）
├── icon.svg               ← 图标矢量源文件
├── icon-maskable.svg      ← Android 自适应图标源文件
├── icon-192.png 等        ← 用 make-icons.ps1 生成的 PNG 图标
├── make-icons.ps1         ← 生成 PNG 图标（.NET 自带库，无第三方依赖）
├── serve-https.py         ← 局域网 HTTPS 测试服务器
├── _check.js              ← 电脑上跑的静态语法/id 校验（可选）
└── README.md              ← 本说明
```

`_check.js` 的用法（需要电脑上有 Node）：

```bash
node _check.js
```

它会编译检查 `index.html` 里的脚本、交叉校验 HTML 与 JS 的 id、粗查括号配平，并输出报告。它和第 4 节的 `?selftest=1` 不是一回事：前者在电脑上静态检查代码，后者在浏览器里实跑业务逻辑断言。

## 七、后续可以加的东西

这些是我建议但**这一版还没做**的，你用了几天后觉得需要再说：

1. **面试问题库** — 把每轮被问到的问题结构化沉淀下来，按公司/岗位/技术点检索，形成自己的题库。
2. **提醒推送** — PWA 已经能装了，下一步可以用通知 API 做「面试前一天提醒」；目前只有打开应用时的倒计时。
3. **多端同步** — 目前纯本地。要同步就得加后端或接云盘 API，会引入账号和网络依赖。
4. **Offer 对比表** — 把几个 Offer 按薪资/地点/转正率/通勤并排放，辅助做选择。
5. **日历导出** — 把截止日/面试时间导成 `.ics`，一键进手机系统日历。
6. **JD 关键词分析** — 统计你投的岗位里出现频率最高的技能词，反过来指导补短板。
